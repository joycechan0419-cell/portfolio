# 个人求职网站 SPEC

## 背景
- 求职者身份：10 年经验 UX 设计师
- 隐含约束：有 2 年 gap 期，社保不体现，**网站与简历一律不展示**
- 求职目标：放宽标签，定位 **「中高级 / 资深设计师 / 设计专家 / 体验设计 Lead」** 等多个层级
- 对标方向：大厂资深设计师个人网站（克制、专业、内容驱动）

---

## 一、用户画像分析

### 画像 A：大厂资深招聘官 / HR BP（首要目标用户）
- 特征：每天从 100+ 份设计师简历中筛选，每份停留 5–8 秒
- 痛点：信息噪声大，无法快速判断"值不值得约面"
- 需求：**3 秒看到定位 / 5 秒看到代表作 / 15 秒看到思考深度**

### 画像 B：设计团队 Hiring Manager / 设计总监
- 特征：每周集中面试 2–3 位候选人，约面前会点开候选人网站
- 痛点：仅看简历信息密度不够，要看设计决策的来龙去脉
- 需求：看到案例的"问题→方案→结果→反思"完整闭环

### 画像 C：设计师同行（推荐 / 引荐流量）
- 特征：通过脉脉、即刻、朋友圈点入
- 痛点：纯审美同好，无明确招聘诉求
- 需求：被设计品味打动后愿意转发、内推

---

## 二、场景故事

**场景 A（首要）：字节设计招聘官 Lily 周五下午快速筛选**
1. 看到一条信息流分享 → 点开个人站（默认中文）
2. 首屏 1 秒读懂：10 年 UI/UX / 主导过 内容·B端·传统 三类业务 / 1 周可到岗 / 客户列表首位爱奇艺
3. 在 Hero 「Next chapter」段落看到「Senior IC / 设计 Lead / 跨业务驱动」3 个明确方向——立即判断是否相关方
4. 滚动 5 秒：看到 3 张代表作卡——爱奇艺跨 4 子业务组件库 / 安徽八建数据驾驶舱 / 芯港 10 客户配置化 PM
5. 选中一个案例点进去：**背景 → 约束 → 探索方案 (A/B/C 对比) → 决策理由 → 执行 → 结果 → 反思 → 可迁移方法** 八段逻辑链
6. 滚到 About：看 3 张能力维度卡片（从 0 到 1 / 跨团队跨客户复用 / 替决策者做减法），每张内含 2 条跨年份证据行（中国美院毕业后 2016 起到至今）
7. 在 Contact 区看到 7 个档级标签并列（高级 / 资深 / Lead / Principal / Manager / 设计专家 / 全栈设计师）+ 邮箱 / 电话一键复制按钮 + toast 反馈
8. 按需一键 EN 切到英文版；或直接复制邮箱 / 复制电话 / 阅读 AI 应用程度章节
9. **45 秒内做出"推进面试"决策**

**场景 B：阿里设计总监主动搜到作品站**
1. 在搜索结果点入（OG 卡片正确展示）
2. 直接跳到 Works，深度阅读 1–2 个完整案例（例如"芯港跨 10 家制造业配置化 PM"）
3. 看完 About 能力维度卡片，了解 3 个核心能力域的实战证据，之后直接邮件联系，约面试

**场景 C：海外招聘官/HR 通过 LinkedIn / Google 进入**
1. 浏览器语言为 `en*` 时，自动落到英文版（顶栏 `EN` 激活）
2. 阅读 Hero lede + 案例五段逻辑链
3. 在 Contact 区切换回中文版或直接邮件联系

**场景 D：同行设计师脉脉 / 即刻动态点入**
1. 浏览首页设计语言与排版
2. 阅读 1 个案例，建立专业认同
3. 在 Contact 区复制联系方式或转发（注：站点不再外链社交平台，减弱"广撒网"姿态）

## 三、功能边界

### ✅ MVP 范围内（必须做）
1. **Hero 首屏**：姓名 / 一句话价值主张（学术型定位）/ 「Next chapter」looking-for 段落 / **7 档求职定位标签并列**（Senior IC / Lead / Manager / Principal / 设计专家 / 全栈设计师 / Product Designer）/ 关键指标 4 项 / 可到岗时间；客户列表首位爱奇艺
2. **Works 案例网格**：**3 个精选代表作**（爱奇艺组件库 / 安徽八建数据驾驶舱 / 芯港跨客户配置化 PM） + 关键数据
3. **Case Detail 案例详情**：**8 段逻辑链**（背景 / 约束 / 探索方案 + A/B/C 对比 / 决策理由 / 执行 / 结果 / 反思 / 可迁移方法，Kartik Rao 框架深化）
4. **About 能力维度**（替代原 timeline）：**3 张能力维度卡片**——按"角色与成果陈列"，不画连续时间轴，让能力叙事先于月份颗粒度
   - **DIM 01 从 0 到 1 的产品体验**：每日互动（2016–17 · 一知 App 全套视觉 + DMP 运营后台）+ 安徽八建（2023–今 · 集团品牌视觉系统 + 4 套核心看板 / 2024–25 优秀员工奖）
   - **DIM 02 让设计在跨团队 / 跨客户里复用**：爱奇艺（2017–20 · 跨 4 子业务组件库沿用同一层）+ 芯港信息（2022–23 · 10 客户配置化 PM / 接入 −67%）
   - **DIM 03 替决策者做减法**：德润环保（2021–22 · 废宝通 + 多套数据驾驶舱）+ 颐家科技（2020–21 · APP 矩阵 + 拉新 H5）
   - 视觉：大号橙红 `dim-num`（56px）+ `dim-title`（28px）+ `dim-desc`（灰色 16px）+ 2 行 `ev-row`（年份 + 简短描述）
   - title 字段统一为 `Product Designer`
5. **Skills 能力矩阵**：8 项抽象能力（UI 视觉 / UX 交互 / 数据可视化 / 动效 / 3D 草图 / 设计系统 / 跨团队协作 / 英语 & 综合）+ 真实工具标签（Sketch / Photoshop / AI / AE / Rhino / CAD / SketchUp / Axure / Xmind 等）
6. **Contact 模块**：邮箱直达 / **邮箱 + 电话一键复制按钮 + toast 反馈** / **7 档岗位开放标签并列** / **无社媒外链**（LinkedIn / 即刻 / Dribbble / 站酷 / Behance 全部不上 — 减弱"广撒网"姿态，强化"在作品里看见我"）
7. **AI 应用程度章节**：4 条量化进度条（视觉探索 85 / 研究文案 80 / 原型 Cursor 65 / Figma AI 70）+ 一段立场陈述「协作伙伴而非替代判断」+ 进入视口时渐入动画
8. **Methods 章节**：3 条可迁移方法（从 3 个案例抽象），含**定义 + 适用场景 + 案例引用**——把作品集与认知能力双呈现
9. **响应式布局**：桌面、平板、手机三档断点
10. **SEO 与社交分享**：OG 卡片 / title / desc（**中英双语切换同步更新**）+ `<meta property="og:image">` 真实头像
11. **中英切换**：顶栏 segmented control (`中` / `EN`) + localStorage 持久化 + `<html lang>` 同步 + meta 同步 + 236 键双字典
12. **顶栏 scroll spy**：滚动时根据当前可视 section 自动给 nav 项加 `.active`（橙色下划线 + 字色加重），让招聘官始终知道"我现在在哪个模块"
13. **右下角回顶按钮**：`<a href="#top">` 46×46 圆形（橙红底白色 linear SVG 箭头），**永远可见**（不依赖 scroll 监听），点击触发原生 hash 跳转 + 3 层保险（点击监听 / 事件委托 / 传统 scrollTo fallback），≤720px 屏缩到 42×42
14. **Cases 模块右侧悬浮目录**：`<aside class="cases-toc">` fixed 右侧、垂直居中，3 个胶囊按钮（爱奇艺组件库 / 安徽八建看板 / 芯港配置化 PM）；整个 Cases 章节在视口里才显示 TOC（IntersectionObserver 阈值 0.05）；进入任一 case 文章时对应按钮加 `.active`（墨黑底白字，IntersectionObserver 监听）；点击平滑滚到对应案例；离开 Cases 章节淡出；≤1280px 屏隐藏避免拥挤

### 🎯 策略对应硬约束（来自六章策略映射）
- **淡化职级**：Hero / 案例卡 / About 三处均不出现 `Senior` / `资深` / `Staff` / `Principal` 等单一职级标签字眼；title 字段统一为 `Product Designer`（中英两版都生效）
- **隐匿 Gap**：About 改为按能力维度组织（3 张 dim 卡片），不画连续时间轴，无月份颗粒度暴露；6 段工作经历被打散重组进 3 个维度中；无 `freelancing` / `learning` / `personal exploration` / `consulting` 等字样；简历 PDF 与站点工作经历对齐
- **放宽目标**：Skills 标签覆盖 IC 与 Lead 双信号（实际 8 项能力矩阵同时包含个人深度与跨团队推动）；案例兼顾"个人深度迭代"与"跨团队推动结果"（案例 01 / 03 为 Lead / 案例 02 为 IC 深度）；Contact 注明开放 7 个档级标签
- **双语策略对齐**：英文版同样执行上述三条策略——不出现策略禁用词、不暴露 gap、title 在 EN 版仍统一为 `Product Designer`（不译为 "Senior Designer" 等）

### ❌ MVP 不做（明确不做）
- 博客 / 文章系统
- 评论 / 留言 / 订阅
- CMS 后端（使用静态站点或 Markdown）
- 用户登录 / 数据埋点
- 在线交互 Demo（仅展示静态截图）
- **不展示任何 gap 期信息**（时间线、简历、自我介绍均不出现）
- 求职目标不写"资深 UX 设计师"（放宽为 7 档级标签并列）
- 不做 ≥ 3 种语言版本（**中/英双语已落地**，其它小语种不做）

## 四、交互流程

### 4.1 主浏览路径
1. **落地 → Hero**：1 秒内读懂定位（Looking-for 段落）+ 到岗时间 + 客户列表首位爱奇艺
2. **下滚 → Works**：浏览 3 张代表作卡
3. **Hover 案例卡**：浮出关键结果数据
4. **点击 → Case Detail**：阅读 8 段逻辑链（含 A/B/C 方案对比 + 可迁移方法提炼）
5. **返回 → About 能力维度**：阅读 3 张 dim 卡片（从 0 到 1 / 跨团队跨客户复用 / 替决策者做减法），每张内含 2 条 ev-row 证据
6. **Methods**：阅读 3 条从案例抽象出的可迁移方法
7. **Skills**：8 项能力矩阵 + 真实工具标签
8. **AI 应用程度**：4 条进度条渐入 + 「协作伙伴」立场
9. **More**：教育 + 兴趣 4 项 + 3 段资深自我评价
10. **底部 → Contact**：发邮件 / 一键复制 / 7 档级标签 / 微信 QR

### 4.2 关键交互细节
- Hero 区双 CTA：「发邮件联系 →」+「**复制电话**」——复制按钮复用 toast 反馈机制，桌面端点击即成功（不依赖客户端唤起）
- **主 CTA 单按钮**：Contact 末尾只剩「发邮件 →」单按钮，无 `tel:` 链接（避免桌面无效点击）
- 案例卡 hover 仅显示一行数据，不遮挡图片
- **About 改能力维度组织**：3 张 dim 卡片替换原 6 段时间线——按"角色 + 成果"聚合，不画连续时间轴
- **Cases 模块右侧悬浮目录**：滚到 Cases 章节时右侧中部出现 3 个胶囊按钮（带数字 + 案例简称）；进入任一 case 文章时对应按钮加 `.active`（墨黑底白字），点击平滑滚到该案例；离开 Cases 章节自动淡出；≤1280px 屏隐藏
- **Contact 联系方式全部用「复制」按钮**：邮箱 / 电话（含微信二维码卡片）点击后写入剪贴板 + toast「已复制」反馈，不再用 `tel:` / `mailto:` 唤起
- AI 章节进度条：进入视口时宽度从 0 渐变到目标值（IntersectionObserver）
- **顶栏 scroll spy**：滚动时根据当前 section 给 nav 加 `.active` + 橙红下划线（IntersectionObserver 触发）
- **右下角回顶按钮**：`<a href="#top">` 46×46 圆形（橙红底白色 linear SVG 箭头），**永远可见**（`opacity: 1` 默认，不依赖 scroll 监听），点击触发原生 hash 跳转 + JS 3 层保险（点击监听 / `document` 事件委托 `closest('#backToTop')` / 传统 `window.scrollTo` fallback），≤720px 屏自动缩到 42×42
- **回顶按钮的「永远可见」策略**：曾用 scroll 监听 + `opacity: 0` 隐藏方式，发现 scroll 事件不可靠（部分浏览器 / 隐身模式不触发），改为「永远可见」更稳。这是产品哲学：重要的导航元素**不依赖 JS 状态**
- **顶栏不外链社媒**：LinkedIn / 即刻 / Dribbble / 站酷 / Behance 全部不上（只剩 `mailto:` / `tel:` / 微信 QR 三个真实的联系方式）
- 移动端汉堡菜单，案例卡全宽堆叠
- **中英切换按钮**：顶栏分段控件（`中` / `EN`），激活态黑底白字；点击切换内容；`<html lang>` 与 meta 同步；选中的语言写入 localStorage，下次进入自动恢复
- **HTML fallback 双写策略**：所有 `data-i18n` 元素的 HTML fallback 文本都已是最新文案（即使 JS 未执行，访客看到的也是新版）

### 4.3 视觉与节奏
- 排版：大字号 + 留白 + 高质量截图
- 动效：克制，最多 200ms 过渡
- 加载：首屏 ≤ 3s
- 颜色：单色 + 1 个强调色，与简历作品页保持专业感

### 6.2 三大策略与对标映射

#### 策略一：淡化职级 → 对标 Kartik Rao
- **原则**：网站读起来像一个"思考者"，而非一张 title 卡片。
- **执行清单**：
  - Hero 不写"Senior UX Designer"，改为 `Product Designer · 10 yrs`
  - 案例卡的主标题是"解决什么问题"，而非"做的什么产品"
  - About 能力维度卡片用"做到了什么 + 带来了什么结果"组织，不用"被称呼什么 title"
  - 简历 PDF 同步：title 字段统一为 `Product Designer`
- **取舍**：放弃"高级感"标签信号，换来跨档级适配（详策略三）。

#### 策略二：隐匿 Gap 期 → 对标 Jean-Marc Denis
- **原则**：用视觉与叙事的**连续性**"抹平"时间断裂——缺失本身不可见；进一步**按"角色 + 能力"重新组织**，把时间维度换成能力维度，让"月份精度"自然不必出现。
- **执行清单**：
  - 时间线展示连续 12+ 个月的项目与产出，**不留空段、不出现 `freelancing` / `learning` / `personal exploration` / `consulting` 等字眼**
  - **About 章节改为 3 张能力维度卡片**（从 0 到 1 / 跨团队跨客户复用 / 替决策者做减法）——按"角色与成果陈列"，每一项能力下聚合 2 段跨年份工作经历作证据，让招聘官按能力对号入座而非按月份对号入座
  - **不画连续时间轴**（圆点 + 左线视觉已删除），替换为"能力叙事"为主轴；月份从"主语"降级为"ev-row 的稀疏标注"
  - "About" 段落无任何 gap 描述
  - 简历 PDF 与站点工作经历对齐
  - 视觉节奏保持匀速，**不留视觉"呼吸段"或视觉留白真空**（这正是 Denis 留白哲学的**反向**应用：留白越多越暴露断裂，所以我们压缩留白）
  - 如确曾有 freelancing 经历，**包装成正式项目**，署名 + 客户类型 + 量化结果
- **取舍**：放弃"按月份排简历"式的诚实姿态，换来"按能力叙事"产品化表达；让招聘官对号入座的是能力而不是空缺。

#### 策略三：放宽求职目标 → 对标 Minsang Choi
- **原则**：用**能力矩阵**覆盖多档级岗位画像，让招聘官自己"对号入座"。
- **执行清单**：
  - **Hero 标签改为多档级并列定位**：如 `Senior IC · Lead · Manager · Principal`，5–7 个层级并列
  - Contact 模块放一行"我开放的方向"：`高级 / 资深 / 主管 / Lead / Principal 岗位均开放`
  - Skills 标签覆盖：用户研究 / 体验策略 / 信息架构 / 交互设计 / 视觉规范 / 设计管理 / 跨团队协作 / Mentor
  - **案例选择兼顾**（本项目实际选型）：
    - IC 深度 → 案例 02「安徽八建数据驾驶舱」：细节 / 决策 / 把传统行业的数字化做厚
    - Lead 信号 → 案例 01「爱奇艺跨 4 子业务组件库」：跨业务线推动、复用率与上手时间指标化
    - 跨客户 Lead → 案例 03「芯港 10 客户配置化 PM」：可配置化业务模板、抽象出通用底座
  - 每条 Job Title 在 About 中**消歧为 `Product Designer`**（中英双语皆如此），让招聘官按能力而非职级对号
- **取舍**：放弃"精准匹配单一岗位"的姿态，换来多档级面试机会。

> 借鉴原则：**只学结构与叙事节奏，不抄视觉与文案**——三家对标的视觉风格差异极大（极简 / 系统 / 逻辑），本站挑**逻辑骨架**而非任何一家的视觉。
